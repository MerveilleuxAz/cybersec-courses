Qu'est-ce qu'une attaque DDoS ?

Le DDoS (Distributed Denial of Service) est une attaque visant à rendre un service indisponible en le saturant avec un volume massif de requêtes provenant de multiples sources distribuées (botnet).

🎯 Objectifs d'une attaque DDoS :

  • Saturation de bande passante : Épuiser la capacité réseau
  • Épuisement des ressources : CPU, RAM, connexions simultanées
  • Perturbation de service : Rendre le site/service inaccessible
  • Extorsion : Demander une rançon pour arrêter l'attaque
  • Distraction : Couvrir une autre attaque plus ciblée

💡 Différence DoS vs DDoS :

DoS (Denial of Service) └─ 1 seule source d'attaque └─ Plus facile à bloquer (bloquer 1 IP) DDoS (Distributed Denial of Service) └─ Milliers/millions de sources (botnet) └─ Très difficile à bloquer (IPs légitimes infectées) └─ Volume beaucoup plus important

⚔️ Types d'attaques DDoS :

1. Attaques Volumétriques (Volume-based)

Saturation de la bande passante avec un énorme volume de trafic.

• UDP Flood : Inondation de paquets UDP • ICMP Flood (Ping Flood) : Envoi massif de ping • DNS Amplification : Exploitation de serveurs DNS → Requête : 60 bytes → Réponse : 3000+ bytes (amplification x50) • NTP Amplification : Exploitation de serveurs NTP

2. Attaques Protocolaires (Protocol-based)

Exploitation des faiblesses des protocoles réseau (couches 3 et 4).

• SYN Flood : Envoi massif de SYN sans ACK → Épuise la table de connexions TCP • Ping of Death : Paquets ICMP surdimensionnés • Smurf Attack : ICMP broadcast amplification • Fragmentation Attack : Paquets fragmentés malformés

3. Attaques Applicatives (Application Layer - L7)

Ciblent l'application web elle-même (couche 7 OSI).

• HTTP Flood : Requêtes HTTP GET/POST massives → Semblent légitimes, difficiles à bloquer • Slowloris : Maintient connexions ouvertes longtemps • Slow POST : Envoi très lent de données POST • Cache-busting : Requêtes vers pages non cachées • XML-RPC Pingback : Exploitation de WordPress

🔓 Serveur Sans Protection

⚠️ Vulnérabilités :

  • ❌ Aucune limitation de débit (rate limiting)
  • ❌ Pas de filtrage d'IP
  • ❌ Timeout serveur par défaut (long)
  • ❌ Pas de mise en cache
  • ❌ Traitement de toutes les requêtes
// ❌ Code vulnérable app.get('/api/data', (req, res) => { // Pas de rate limiting // Requête lourde en BDD db.query('SELECT * FROM huge_table'); res.send(data); }); // → Peut être surchargé facilement
Impact d'une attaque :
• Serveur indisponible en 30 secondes
• Tous les utilisateurs affectés
• Perte de revenus
• Dommage à la réputation

✅ Serveur Protégé

✅ Protections actives :

  • ✅ Rate Limiting : Max 100 req/min par IP
  • ✅ WAF : Filtrage du trafic malveillant
  • ✅ CDN : Distribution géographique
  • ✅ Load Balancing : Répartition de charge
  • ✅ Auto-scaling : Ressources dynamiques
  • ✅ Captcha : Validation humaine sous attaque
// ✅ Code protégé const rateLimit = require('express-rate-limit'); const limiter = rateLimit({ windowMs: 60 * 1000, // 1 minute max: 100, // 100 requêtes max message: 'Trop de requêtes' }); app.use('/api/', limiter); // Mise en cache app.use(cache('5 minutes')); // Timeout app.use(timeout('10s'));
Résistance à l'attaque :
• Trafic légitime maintenu
• IPs malveillantes bloquées
• Service disponible 99.9%
• Détection et mitigation automatique

🤖 Botnets et attaques DDoS réelles :

Qu'est-ce qu'un Botnet ?

Réseau d'ordinateurs/objets IoT infectés contrôlés à distance pour lancer des attaques coordonnées.

Botnet Mirai (2016) ├─ 600,000 dispositifs IoT infectés ├─ Attaque de 1.2 Tbps contre OVH ├─ DNS provider Dyn rendu indisponible └─ Impact : Twitter, Netflix, Reddit, GitHub inaccessibles Botnet Memcached (2018) ├─ 1.7 Tbps contre GitHub ├─ Amplification x51,000 └─ Mitigation en ~10 minutes (CDN Akamai)

Motivations des attaques DDoS :

  • Extorsion : Rançon pour arrêter l'attaque (DDoS-for-ransom)
  • Concurrence déloyale : Saboter un concurrent
  • Hacktivisme : Protestation politique (Anonymous)
  • Représailles : Vengeance personnelle
  • Diversion : Cacher une intrusion/vol de données

🛡️ Stratégies de défense contre DDoS :

Niveau Infrastructure :

  • CDN (Cloudflare, Akamai) : Absorption du trafic distribué
  • Anti-DDoS spécialisés : Arbor Networks, Radware
  • Over-provisioning : Bande passante excédentaire
  • Anycast routing : Distribution géographique du trafic

Niveau Applicatif :

  • Rate Limiting : Limitation par IP/session (nginx, express-rate-limit)
  • WAF (Web Application Firewall) : Filtrage intelligent
  • Captcha Challenge : Vérification humaine (hCaptcha, reCAPTCHA)
  • Connection Limiting : Max connexions simultanées par IP
  • Caching agressif : Varnish, Redis

Détection et Monitoring :

  • Baseline de trafic : Connaître le trafic normal
  • Alertes anomalies : Détection de pics suspects
  • Analyse de patterns : User-Agent, géolocalisation
  • Honeypots : Leurres pour identifier attaquants

Plan de réponse incident :

  • Playbook DDoS : Procédure documentée
  • Contact ISP : Coordination avec fournisseur internet
  • Null routing : Blackhole du trafic malveillant
  • Communication : Informer utilisateurs et partenaires
