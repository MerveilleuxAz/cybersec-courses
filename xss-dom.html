Qu'est-ce que le XSS DOM-based ?

Le XSS DOM-based est une vulnérabilité où le code malveillant est exécuté à la suite d'une modification du DOM (Document Object Model) par du JavaScript côté client. Le serveur n'est jamais impliqué dans l'attaque.

🎯 Caractéristiques uniques :

  • Côté client uniquement : La vulnérabilité est dans le JavaScript, pas le serveur
  • Pas de requête HTTP : Le payload n'est jamais envoyé au serveur
  • Fragment d'URL (#) : Souvent exploité via le hash de l'URL
  • Plus difficile à détecter : Les WAF ne voient pas le payload

💡 Exemple d'attaque :

# URL malveillante https://site.com/welcome.html#<script>alert('XSS')</script> # Code JavaScript vulnérable var name = location.hash.substring(1); document.getElementById('welcome').innerHTML = "Bienvenue " + name; # Le fragment (#...) n'est jamais envoyé au serveur # Mais le JS client l'utilise directement dans innerHTML # → XSS exécuté sans que le serveur le sache !

🔓 Page Vulnérable

Testez avec ces URLs :

#<img src=x onerror="alert('XSS DOM!')"> #<script>alert('Hack!')</script> #<svg onload="alert('XSS')">

Cliquez sur "Charger la page" pour voir le résultat

⚠️ Code vulnérable :

// ❌ VULNÉRABLE - Sources DOM non validées // Récupération directe du hash var userInput = window.location.hash.substring(1); // OU du query string var name = new URLSearchParams( window.location.search ).get('name'); // Injection directe dans le DOM document.getElementById('div').innerHTML = "Bonjour " + userInput; // ❌ Autres sources dangereuses : // - document.URL // - document.documentURI // - document.referrer // - window.name

Sources DOM dangereuses : location.hash, location.search, document.referrer, window.name

✅ Page Sécurisée

Les mêmes payloads seront neutralisés :

Cliquez sur "Charger la page" pour voir le résultat

✅ Code sécurisé :

// ✅ SÉCURISÉ - Validation + textContent var userInput = window.location.hash.substring(1); // Validation stricte if (!/^[a-zA-Z0-9\s]+$/.test(userInput)) { userInput = "Invité"; } // Utiliser textContent au lieu de innerHTML document.getElementById('div').textContent = "Bonjour " + userInput; // OU créer des éléments DOM var text = document.createTextNode( "Bonjour " + userInput ); div.appendChild(text);

Protections :

  • ✅ Validation des entrées DOM (whitelist)
  • ✅ textContent au lieu de innerHTML
  • ✅ Encodage contextuel des données
  • ✅ Éviter eval(), setTimeout(string), Function()

🔍 Sources et Sinks DOM dangereux :

Sources (Origines des données) :

// Sources contrôlées par l'attaquant location.hash // #payload location.search // ?payload location.href // URL complète document.URL // URL du document document.documentURI // URI du document document.referrer // Page précédente window.name // Nom de la fenêtre postMessage() // Messages entre fenêtres

Sinks (Destinations dangereuses) :

// ❌ Exécution de code eval(userInput) setTimeout(userInput, 100) setInterval(userInput, 100) Function(userInput)() new Function(userInput)() // ❌ Modification DOM dangereuse element.innerHTML = userInput element.outerHTML = userInput document.write(userInput) document.writeln(userInput) // ❌ Navigation dangereuse location = userInput location.href = userInput location.assign(userInput)

⚔️ Scénarios d'attaque DOM XSS :

1. Redirection dynamique vulnérable

// ❌ Code vulnérable var redirect = new URLSearchParams(location.search).get('next'); window.location = redirect; // 🎯 Attaque https://site.com/?next=javascript:alert('XSS')

2. Création dynamique de contenu

// ❌ Code vulnérable var lang = location.hash.substring(1); document.write("<script src='/js/" + lang + ".js'></script>"); // 🎯 Attaque https://site.com/#'><script>alert('XSS')</script>

3. jQuery DOMXSS

// ❌ Code vulnérable var username = location.hash.substring(1); $('#welcome').html('Bienvenue ' + username); // 🎯 Attaque https://site.com/#<img src=x onerror=alert('XSS')>

🛡️ Défenses contre DOM XSS :

1. Éviter les Sinks dangereux

  • ✅ Préférer textContent à innerHTML
  • ✅ Créer des éléments DOM : createElement(), createTextNode()
  • ✅ Éviter eval() et setTimeout(string)
  • ✅ Utiliser setAttribute() pour les attributs

2. Valider et encoder les Sources

  • ✅ Whitelist stricte : /^[a-zA-Z0-9]+$/
  • ✅ Encodage contextuel : HTML, JavaScript, URL
  • ✅ Bibliothèques : DOMPurify pour sanitization

3. Content Security Policy (CSP)

Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'

4. Outils de détection

  • ✅ DOM Invader (Burp Suite extension)
  • ✅ eslint-plugin-no-unsanitized
  • ✅ Analyse statique du code (SAST tools)
