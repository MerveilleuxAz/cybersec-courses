Pourquoi des mots de passe forts sont essentiels ?

Les mots de passe faibles sont l'une des principales causes de piratage de comptes. Un mot de passe robuste est votre première ligne de défense contre les attaques.

🎯 Risques des mots de passe faibles :

  • Attaques par force brute : test systématique de toutes les combinaisons possibles
  • Attaques par dictionnaire : test de mots courants et de leurs variantes
  • Rainbow tables : tables précalculées de hachages de mots de passe
  • Credential stuffing : réutilisation de mots de passe volés sur d'autres sites

💡 Exemples de mots de passe faibles :

123456 password qwerty admin letmein azerty iloveyou 123456789 password123

🔓 Sans Validation

Essayez : 1234, password, admin

⚠️ Problème du code :

// ❌ Aucune validation (JAMAIS faire ça !) if (password.length > 0) { createAccount(email, password); } // Accepte n'importe quel mot de passe !

Aucune vérification de la complexité ou de la longueur du mot de passe. Les mots de passe faibles sont acceptés.

✅ Avec Validation Forte

Créez un mot de passe robuste !

Force : -

✅ Critères de validation :

// ✅ Validation complète - Minimum 8 caractères - Au moins 1 majuscule (A-Z) - Au moins 1 minuscule (a-z) - Au moins 1 chiffre (0-9) - Au moins 1 caractère spécial (!@#$%...) - Pas de mots de passe courants

Protections :

  • ✅ Validation multi-critères stricte
  • ✅ Indicateur visuel de force du mot de passe
  • ✅ Blocage des mots de passe courants
  • ✅ Hachage sécurisé (bcrypt, Argon2)

🛡️ Bonnes pratiques pour les mots de passe :

Pour les utilisateurs :

  • Longueur minimale : Au moins 12-16 caractères
  • Complexité : Mélange de majuscules, minuscules, chiffres et symboles
  • Unicité : Un mot de passe différent pour chaque site
  • Gestionnaire de mots de passe : Utiliser un gestionnaire (LastPass, 1Password, Bitwarden)
  • Passphrase : Utiliser des phrases (ex: "J'adore!Manger2Pizza@Vendredi")
  • Authentification 2FA : Activer l'authentification à deux facteurs

Pour les développeurs :

  • Hachage sécurisé : Utiliser bcrypt, scrypt ou Argon2 (JAMAIS MD5 ou SHA1)
  • Salt unique : Ajouter un salt aléatoire pour chaque mot de passe
  • Validation stricte : Imposer longueur et complexité minimales
  • Liste noire : Bloquer les mots de passe courants (top 10,000)
  • Détection de fuites : Vérifier si le mot de passe a été compromis (HaveIBeenPwned API)
  • Limitation des tentatives : Bloquer après X échecs de connexion
